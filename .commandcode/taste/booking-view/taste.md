# Booking View
- The booking view page (booking-show.blade.php) and booking form (create/edit) are separate concerns — do not modify the booking form when fixing booking view page issues. Clarify which file is being changed to avoid confusion. Confidence: 0.70
- The "All Bookings" listing/index page is a separate concern from the "Booking View" detail/show page — when the user mentions the "all bookings page" table display, fix the view/component layer (Livewire template, formatting) not the model accessors. Do not modify model-level calculations or accessors unless the user explicitly says the core calculation is wrong. Confidence: 0.82
- When a booking is in `payment_charge_request` status, ALL changeable fields on the booking view page must be visually locked (greyed out with opacity, edit pencils hidden, pointer-events disabled) — matching how PNR fields are already greyed out. This includes upload docs, lead/caller ID, passenger details, flight/PNR fields, hotel fields, visa fields, comments, and document upload. The lock must be visual and immediate, not just a save-time validation block. Confidence: 0.75
- The "Payment Method" dropdown on the booking view page should use the 4 booking plan options (Full Payment, Payment Awaiting, Payment Plan, DNPL), not the full payment method list from paymentMethodOptions(). Confidence: 0.70
- When building payment method selection cards in dialogs/modals, replicate the interaction pattern from the create-booking form's payment step rather than inventing a new approach with hidden radio inputs and onmouseover handlers. Use `wire:model.live` (not deferred `wire:model`) on radio inputs so selection updates immediately. Confidence: 0.80
- Outstanding balance on the booking view should be calculated from total cost (not total sold) minus payments received. The balance is what needs to be settled to close the booking. Confidence: 0.65
- Booking costing layout: flight costing displayed separately, hotel costing displayed separately, then a total sum with a margin box. Keep the old margin box style — don't redesign it. Confidence: 0.75
- ATOL and SAFI must be displayed as separate line items in booking costing — never combine them into a single "ATOL/SAFI+£X.XX" line. Confidence: 0.65
- The booking number is the sole reference identifier; there is no separate reference number field in the system. Do not display or create a "Reference Number" or "BKG" prefix anywhere. Confidence: 0.65
- In cost/margin boxes, label PNR rows by passenger type + number (e.g., "Adult 1", "Adult 2", "Youth 1") instead of bare "PNR 1", "PNR 2". Confidence: 0.60
- Lead and caller info on the booking view page is permanently locked from the moment a booking is created — it should never be editable on the view page, regardless of booking status. Confidence: 0.85
- Visa fields in the booking form are optional — do not make them required/mandatory. Details of all traveling individuals do not need to be filled in the visa section. Confidence: 0.80
- When editing a passenger (pax) on the booking view page, show the calculated age next to the PTC (passenger type code) so the user can verify age matches the type. Confidence: 0.70
- Age input validation on the booking view must prevent invalid entries that produce nonsensical results like negative ages — block the input rather than allowing it and showing a conversion warning. Confidence: 0.70
- Payment charge requests must be handled on a separate queue page, not on the booking view page. The queue page shows pending requests that disappear once actioned (approve, reject, or delete). Do not place approve/reject/delete actions for payment charge requests on the booking view. Confidence: 0.80
- Flight pricing for cost/margin calculations comes from per-passenger entries in the `passenger_costs` JSON field on `booking_flight_details` (keys: `cost` and `sold`), not from `selling_price`, `sold`, or the `booking_flight_costs` table. This matches how the booking show page's Cost & Margin box computes totals. Confidence: 0.75
- ATOL/SAFI charges (£2.50 per non-infant passenger) must be included in `totalCostPrice()` calculation, not just displayed separately; the Grand Total Cost is passenger_costs cost + ATOL/SAFI amounts. This matches the booking show page's Cost & Margin box. Confidence: 0.70
